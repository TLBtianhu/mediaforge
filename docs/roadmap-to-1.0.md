# MediaForge 1.0 整改路线图

1.0 的目标是让用户在本机完成素材导入、模型处理或工作流编排、预览、编辑和导出。桌面和 Agent 从同一套能力契约获取选项，共享任务账本和执行配额。已声明支持的平台和后端应有可重复的安装、运行时准备、真实推理和升级证据。

基线为 2026-11-12 的 Windows `0.0.34 r3`，候选构建提交为 `81d0006`。已有静默覆盖安装和 CUDA 运行时保留记录。旧审查中的单条账本写入同步、插件视图 CSP、回收目录白名单和 MCP token 比较已有后续修复。路线图按数据安全、交付可用性和覆盖范围排序。 [候选与修复记录](handoff-2026-11-08.md#1149-0034-候选重建静默安装与运行时资产2026-11-12) · [架构蓝图](architecture-blueprint.md)

## P0 · 数据安全，本批整改

| 整改项 | 验收条件 |
| --- | --- |
| 消除通用回收绕过 | 渲染层无法调用接受任意文件路径的回收命令。正常结果与工程删除仍通过原生引用检查和预检。用隔离夹具验证被任务、素材库或工程引用的文件及打开的工程得到保护，合法回收仍可执行。 |
| 恢复中断的批量删除 | 在 catalog 锁内恢复可判定的当前格式事务。覆盖只移动了部分记录、提交后清理中断、再次恢复以及 Rust/Python 互读。恢复后全量和增量账本一致，音频 primary/child 引用完整。对损坏、归属未知或相互冲突的文件保留原件并给出诊断。 |

本批已移除通用路径回收入口。账本删除使用目录原子改名作为提交点，恢复只移动或清理当前 schema 2 的暂存记录。手工历史保留到显式删除。文件回收失败应保留本次全部任务记录。 [账本契约](job-ledger-contract.md#批量记录删除与进程中断恢复)

### P1 本批完成项

- **DSH bundle 定位。** 相对插件入口从链接的 bundle 定位该实例的 bootstrap、bridge、数据、模型和运行时。使用已安装 DSH 0.2.2-rc.1 的真实解析器、Cordis 和 MCP 客户端，在独立 profile 中验证了默认安装、自定义目录和便携版布局。三种布局分别加载并实际调用 `mediaforge_status` 三次，均返回所选实例的数据根，profile 的 `cordis.patch.yml` SHA-256 保持一致。
- **运行时选包。** Windows x86_64 CUDA 使用托管 ZIP，Linux x86_64 CUDA 使用 Linux worker 安装。Windows/Linux x86_64 的 CPU、ROCm 各走 worker，macOS arm64 使用随包 MLX。其它目标组合在下载前拒绝。已可用的运行时不会触发替换为 Windows CUDA 的首次使用提示。跨平台验收采用目标矩阵用例，Linux/macOS 原生装机验证仍在 P2。
- **验证记录。** 本批 Windows 无界面验证通过。前端 1,815 项通过、3 项跳过，Rust 526 项通过、2 项忽略，Python 1,742 项通过、5 项跳过。前端生产构建与 6 项静态检查通过。发布时需要生成并签发 schema 3 版本清单。 [运行时规则](../DEVELOPMENT.md)

### P1 执行器进程回收与异常恢复

- **进程与管道。** 桌面与 Agent 共用监督进程，通过 Windows Job Object 或 POSIX 进程组管理 worker 和后代。正常结束回收仍存活的后代，取消和执行器异常退出通过控制管道触发回收。执行器等待监督进程退出并关闭管道后释放主租约。
- **配额和账本。** 监督进程在放行 worker 之前领取配额和任务所有权的回收租约，直到进程树退出。执行器强制退出期间，同一数据根仍保留对应槽位和记录保护，之后才允许接纳下一个任务或恢复为 `interrupted`。 [账本契约](job-ledger-contract.md#共享处理任务配额)
- **音频临时文件。** 收据由 Rust 绑定到直接监督进程，worker 校验监督进程及 Windows 虚拟环境启动器的身份。取消后，Rust 在回收完成时只清理匹配任务收据的临时文件。
- **验证记录。** Windows Rust 全量通过 545 项，忽略 2 项，另用 Python 3.12 venv 验证了音频收据。Windows Python 3.12 专项通过 186 项，覆盖三种生命周期、清理失败重试、原子替换重试及打包资源。Python 全量运行 1,762 项，跳过 5 项，直接运行的音频探针有 1 次异常退出，隔离专项复测通过。WSL Ubuntu 通过真实进程生命周期、配额及编辑器回归。6 项静态检查通过，全程无 GUI。

## P2 · 平台覆盖与长期能力

- **平台和模型矩阵。** 对拟声明支持的 macOS/Linux 原生包和各后端验证自包含运行时、首次启动、真实权重推理、更新后数据保留及退出。补齐已有 SQLite 素材库的跨平台精确引用读取。对仍保守保留文件或拒绝工程清理的平台说明当前行为。 [媒体验证](media-verification.md)
- **Agent 工作流。** 逐项验证公开能力可发现、可校验、可审批、可取消并可查询终态。对图像、视频和音频产物报告可量化的检查结果。在这套基础上推进内置 Agent 与模型网关。 [架构现状](architecture-status.md)
- **可选范围。** 应用自动更新、跨进程全局 FIFO 和物理 GPU 分区按产品需求单独排期。当前执行器各自 FIFO，同数据根共享 worker 配额。

## 本批验证范围

使用独立临时数据根和 Python 3.12 运行回归。Windows 非交互子进程隐藏控制台，构建日志和一次性输出归入 `.tmp/`。本批全程无 GUI、无桌面操控、无用户 profile。原生桌面验收保留为后续独立项目，待允许在专用环境执行时记录结果。

本批 Windows 隔离回归通过。前端全量测试和生产构建通过，Rust 522 项通过、2 项忽略，Python 1,740 项中 1,735 项通过、5 项跳过，6 项静态检查通过。新增的跨语言测试让 Python 写入进程在暂存首条记录后退出，由 Rust 恢复该批记录，并验证 Python 能清理 Rust 端构造的已提交状态。
