## 1. 项目是什么

MediaForge：Windows 桌面媒体处理应用（音频分离 + 图像/视频处理），Tauri 三层结构：

| 层 | 位置 | 说明 |
|---|---|---|
| 前端 | `src/`（Vue 3 + TS + Vite + Naive UI） | 组件自动导入，不要手写 Naive UI import |
| 后端 | `src-tauri/`（Rust） | 编排 worker、安装/升级、运行时资产、命令面 |
| Worker | `python/` | 进程内执行；音频核心在外部 `pymss` 包，图像/视频是自己的 `media_ops` |

分发有三种形态，**数据根必须互不相同**：

| 形态 | 程序位置 | 数据根 |
|---|---|---|
| 开发 | `src-tauri/target/{debug,release}` | 仓库 `.dev-data`（`scripts/dev.ps1`） |
| 便携 | 任意解压目录，带 `mediaforge.portable` 标记 | `<exe 目录>\data` |
| 安装 | `%LOCALAPPDATA%\Programs\MediaForge` | `%USERPROFILE%\.mediaforge` |

数据根可用 `MEDIAFORGE_DATA_ROOT` 覆盖（`src-tauri/src/storage.rs::data_root_dir`），
运行时资产在 `<数据根>\runtime-envs\<assetId>`，激活指针 `runtime-envs/active-runtime.json`。

## 6. 工作约束（这次踩过的坑，务必遵守）

1. **三形态隔离（AGENTS.md 强制）**：开发用 `scripts/dev.ps1`，干净包验证用 `scripts/clean-test.ps1`；
   **绝不拿 `%USERPROFILE%\.mediaforge`（真实用户/狗粮数据）做测试**。E2E 一律用临时 `MEDIAFORGE_DATA_ROOT`。
2. **不要随手跑 `integrations/dsh-mediaforge/register.ps1`**：它会改写 DSH 的 `cordis.patch.yml`，
   触发所有会话的 profile 重载。确有需要先备份，并说明理由。
3. **推送走 SSH**：`git push git@github.com:TLBtianhu/mediaforge.git main`。
   HTTPS 到 github.com 会被连接重置（`gh` 的 API 走 api.github.com，是通的）。
4. **不要用 `gh run watch` 之类的长阻塞后台任务等 CI**。旧会话就是因此进入"挂起等任务"状态，
   期间用户消息被吞。要查 CI 就短轮询 `gh run view <id> --json status,conclusion,jobs`。
5. **CI 只手动 dispatch / PR 触发**，push 不触发，别指望推完自动跑。
6. **不要并发改仓库**：同一时间只能有一个 agent 动这个工作树。
7. 测试脚本若写注册表（如 `HKCU\Software\MediaForge\InstallDir`），必须**先备份、结束恢复**——
   `smoke-upgrade.ps1` 已有范本（卸载会删整个键，恢复前要 `New-Item -Force` 重建）。
